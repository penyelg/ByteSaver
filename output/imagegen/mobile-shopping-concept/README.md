# ByteSaver mobile design proposal

Generated with the built-in ImageGen tool. These images are design proposals, not implemented application screens. Demo identities, photos, dates, and prices are illustrative.

## Boards

- 01-shopping.png: Browse, search/filters, listing details, saved cart, reservation sheet, reservation payment.
- 02-selling-reservations.png: My listings, proposed multi-step create-listing form, item details, review/submit, buying reservations, selling reservations.
- 03-account-verification.png: Sign in, create account, ID submission, pending verification, account, alternative rejected/suspended states.

## Implementation notes

Preserve existing behavior and validation when implementing. Use actual Google avatars when available with initials fallback. The account-state examples are separate alternatives, never a combined production screen. ID rejection and account suspension are separate decisions; the illustrative suspension reason should be replaced with the actual admin-provided access reason. Use the actual location (Isabel, Leyte); the generated seller review screen contains a placeholder Metro Manila location. The upload thumbnails should all depict the same item. Use real configured reservation fee and duration, actual statuses, and current form requirements. Listing creation steps are proposed layout changes. These boards show primary pages and selected states, not every form/error/loading variation.
